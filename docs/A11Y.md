# Accessibility — deep-dive (Phase 2c)

> Semantic tree, keyboard focus, live regions. Competes with Flutter's
> `Semantics` widget + `flutter_semantics` and Qt's QAccessible — pure Zig,
> no GC, no runtime. The OS bridges (AT-SPI, NSAccessibility, UIA, TalkBack,
> ARIA) plug into one C-ABI interface (ADR-0009).

## Architecture

```
ui/semantics.zig    Semantics (per-node descriptor), semantic tree (flatten),
                    FocusManager (keyboard focus + focus ring), live regions,
                    SemanticsBridge (C ABI) + LogBridge (default, records)
ui/node.zig         Node.semantics (owned descriptor), Node.exclude_semantics,
                    Node.mapRectToRoot (bounds → window space)
ui/input.zig        Key.up/down/space + KeyEvent.shift; dispatchKey returns
                    whether the focused node handled the key
host.zig            Tab → focus manager (never reaches the tree); unhandled
                    keys fall back to semantic activation; the focus ring is
                    painted over the tree before end_frame; tree-dirty notify
widgets/*.zig       roles attached in the factories (Text .text, Button
                    .button, Toggle .toggle, Checkbox .checkbox, Radio .radio,
                    Slider .slider + on_key arrows, TextField .text_field,
                    Chip .button, Icon/Image .image)
a11y_main.zig       demo app (focus order, keyboard activation, live region)
```

## The semantic tree

Each widget factory attaches a `Semantics` descriptor to its node
(`ui.semantics.attach(node, .{ .role = .button, .focusable = true, ... })`).
`buildSemanticTree(root)` flattens the widget tree into the view assistive
tech consumes:

- Nodes **without** a descriptor are transparent — their children are lifted
  into the parent's list.
- `Node.exclude_semantics = true` hides a decorative subtree entirely.
- A role's `label` falls back to the first descendant with a label (a
  Button's label is its Text child).
- Signal-driven state stays in sync: Toggle/Checkbox/Radio keep `checked`
  current, the Slider keeps `value` current (`"45%"`) — both via a subscribe
  callback that also repaints.

## Keyboard focus

`FocusManager` (process-global, `setCurrentFocus` — single-window P0, like
the router):

- **Tab / Shift+Tab** move the focus through the focusable nodes in
  semantic-tree order (wraps around). Tab never reaches the widget tree.
- **Enter / Space** activate the focused node: a synthesized down+up at the
  node's center, delivered straight to its `on_pointer` (bypasses the
  router's hit-test on purpose — the deepest child would receive child-local
  coordinates).
- **Arrows** go to the focused node first (the router dispatches them); the
  Slider's `on_key` adjusts its value (±5% per press).
- `focusNode` fires the `focused_sig` signal, moves the input router's focus
  (TextField editing keeps working), damages the old + new ring regions, and
  notifies the bridge (`focus_changed`).

The host paints the **focus ring** over the tree (4 fillRects, no stroke
primitive — no ABI change): a 2 px ring, 3 px outside the focused node's
bounds, mapped to window space through transformed ancestors
(`mapRectToRoot`). Color/width are configurable on the manager.

## Live regions + the bridge

```zig
ui.semantics.announce("3 items added", .polite); // live region
```

`SemanticsBridge` is the C-ABI interface an OS bridge implements
(`fn_ptr` + `userdata`, ADR-0009): `tree_dirty` (structure/layout changed),
`focus_changed`, `announce` (with the region politeness). The default is
`LogBridge`, which records every event — testable headless, and a11y never
crashes the app.

## OS bridges (the 6)

| Platform | Bridge | Status |
|---|---|---|
| Linux | AT-SPI2 over D-Bus | Interface ready; the bridge lands with the Linux target (Phase 3a) — it needs a session bus + the AT-SPI registry daemon, neither exists on the dev Mac |
| macOS | NSAccessibility | Phase 3 (macOS target) |
| Windows | UI Automation | Phase 3 (Windows target) |
| Android | TalkBack (AccessibilityNodeInfo) | Phase 3 (Android target) |
| iOS | UIAccessibility | Phase 3 (iOS target) |
| Web | ARIA (DOM) | Phase 3 (WASM target) |

## Demo + tests

- Demo: `zig build a11y` — heading, TextField, Button, Toggle, Slider. The
  headless smoke scripts the keyboard (Tab ×4, Enter, Space, ←, announce).
- Unit tests: flatten (roles, label fallback, exclude_semantics, nesting),
  focus order (next/prev wrap), focusNode (signal + router + bridge),
  handleKey (tab/shift+tab/enter/space activation), announce + LogBridge.
- Golden: the focus ring paints around the focused node (exact pixels; the
  center stays the widget's color).
- Demo test: focus order = [TextField, Submit, Toggle, Slider], Enter
  submits, Space flips the toggle (semantic `checked` synced), ← moves the
  slider (semantic `value` synced), announcements recorded.
